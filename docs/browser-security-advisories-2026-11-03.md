# Browser security advisories checked on 2026-11-03

## Chrome versions and scope

Google's October 27 desktop stable release includes fixes for all four CVEs below. The released Linux version is **156.0.8078.73**; Windows and macOS received 156.0.8078.73/.74. Google rates all four Critical. [Google release advisory](https://chromereleases.googleblog.com/2026/10/stable-channel-update-for-desktop_0562499947.html)

The Chrome CNA records above do **not** say these are confined to early Chrome 156, and do not supply an introduction version or lower bound. Versions 149 and 154 fall below the stated fixed version. Treat them as unpatched/potentially affected; claiming that each of those versions is demonstrably exploitable by each CVE would go beyond the public evidence. Establishing exact older-branch applicability requires vulnerable-code or fix-history analysis. The four linked Chromium issues exposed only a sign-in page during this check, so that analysis could not be completed from their public details. Google explicitly says security bug details can remain restricted while fixes roll out. [Google disclosure note](https://chromereleases.googleblog.com/2026/10/stable-channel-update-for-desktop_0562499947.html)

## Playwright's sandbox defaults and limits

Playwright documents `chromiumSandbox` as **false by default**, including `launch`, `launchPersistentContext`, and `launchServer`. Its Chromium launcher adds `--no-sandbox` unless that option is explicitly `true`. Custom arguments can still undermine a requested sandbox: the launcher appends caller-supplied arguments afterward. This is an upstream default, not evidence of how any particular local program launches its browser. [Playwright API](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-option-chromium-sandbox), [launcher source](https://raw.githubusercontent.com/microsoft/playwright/main/packages/playwright-core/src/server/chromium/chromium.ts)

The browser's internal sandbox limits compromised renderer processes' access to the operating system. It does not place the whole browser, its privileged controller, or the Playwright process inside an external isolation boundary. Chromium documents separate renderer and browser processes; its sandbox design identifies the browser as the privileged broker, and its FAQ notes that a privileged process performs allowed operations for sandboxed processes. Enabling the internal sandbox therefore cannot be assumed to contain a vulnerability whose stated impact is code execution outside it, such as CVE-2026-118306. This final containment conclusion is an inference from the architecture and CVE description. [Chromium architecture](https://www.chromium.org/developers/design-documents/multi-process-architecture/), [sandbox design](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/design/sandbox.md), [sandbox FAQ](https://chromium.googlesource.com/chromium/src/+/HEAD/docs/design/sandbox_faq.md)

Playwright also states that its Docker image runs browsers as root by default, which disables Chromium sandboxing. For untrusted sites it recommends a separate user and a seccomp profile permitting required user-namespace operations; the image itself is intended for testing/development and is not recommended for visiting untrusted websites. [Playwright Docker guidance](https://playwright.dev/docs/docker)

Updating the actual executable used by the automation and checking its effective launch arguments are necessary follow-up checks. Playwright cautions that compatibility with arbitrary alternate browser executables is not guaranteed, so an executable override needs compatibility testing. No browsers were launched, packages built, configurations edited, or exploits tested for these findings. [Playwright executable-path documentation](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-option-executable-path)
